# Aqaba Yard — Working Rules

## Project

Arabic-only container yard website for the single Aqaba yard.
Fastify + node:sqlite server, React + Tailwind RTL client, shared pure rules.
Specification: SPEC.md. Session log: PROGRESS.md. Standalone repository —
nothing here may import from or depend on the old desktop project.

## Before writing code

1. Read PROGRESS.md, then the SPEC.md sections that matter.
2. For new scope: plan first, wait for the owner's approval.

## Hard rules

- The map IS the application. Every yard operation starts on the yard drawing;
  a form-first flow needs the owner's explicit approval first.
- TypeScript strict. No `any`, no `@ts-ignore`, no `as unknown as`.
- `src/shared` stays pure: no fetch, no DB, no DOM.
- The server is the only authority; client checks mirror it for UX only.
- Soft delete only. The wire carries error CODES; Arabic sentences live in
  `src/client/ar.ts` alone — **clear formal Arabic** (the owner's call:
  «عربية رسمية واضحة»), Western digits, and the official plan's own place
  words (يارد، زون، باي، ستاك، طابق). Imperative for what the user should do,
  «تم …» for what the system did, and every refusal a full sentence naming the
  cause then the remedy. The one server-side exception is `store.OWNER_NAME`,
  a role label the registers print.
- Gravity, not refusal: lifting a container brings everything resting on it
  down one tier, each descent its own `DROP` movement. Only a blocked landing
  refuses (`BLOCKED_DESCENT`).
- **Three tiers, always, everywhere** (`TIERS` = A, B, C). Capacity is stacks
  × 3 and the free-space figures count all three. The owner considered making
  the third an opt-in per bay and decided against it — do not reintroduce it.
- Tailwind logical properties only: `ms-4` not `ml-4`.
- The yard's shape is the OFFICIAL ASEZA plan: committed pure data in
  `src/shared/asezaLayout.ts`, generated by `tools/decode-aseza-pdf.mjs` from
  the authority's newer drawing («new aseza  yard_recover (5) 111-Model.pdf»)
  and locked by tests to the slots counted on it (A 305, B 376, C 54, D 50,
  E 176, F 48, G 24, H 14, J 6 — 1053; letter I skipped). Count from the
  drawing — the owner's call — never from its printed cyan figures. The first
  plan's 681 slots (frozen in `tests/fixtures/asezaLayout681.ts`, generated
  by `tools/decode-aseza.mjs` from `Aseza yard.xlsx`) all stand unchanged in
  it, and the decoder refuses to write if one moves. Never hand-edit a
  generated file; fix the decoder and regenerate.
- **Everything modelled is SAHA 2.** All nine zones are yard 2, so every
  address reads `2-…`. The owner's yards 1 and 3 are separate grounds not
  modelled yet — when one arrives, `yardOf` stops being a constant and reads
  the layout.
- Never invent an unspecified requirement. Ask.

## Verification

`bun run typecheck`, `bun run test` and `bun run lint` must pass before every commit.
